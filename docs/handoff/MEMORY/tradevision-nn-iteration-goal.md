Itamar pushed back (rightly) on framing the gut-feel NN as "win/loss prediction failed." Predicting **how bad a loss will be** is exactly what he wants — it lets the system size leverage per trade and skip bad-odds entries. The win/loss-direction AUC≈0.49 is fine to set aside; the usable signal is loss-severity (MAE Spearman 0.758).

**The program (autonomous, ≥3 fine-tuning rounds, runs while Itamar is away — session d7184e74):**
- Use the saved 5.5M dataset in `gs://tradevision-lab-data/gutfeel_out/` (no regeneration). Train on a GPU VM (T4 spot, auto-delete + watchdog + budget; never touch `labworker`). Per-epoch checkpoints + live loss + save all artifacts to GCS each round. Anti-overfit gates (walk-forward, shuffle, matched baselines). Honest report each round.
- **Measure precisely:** (1) of trades the model flags "bad," how many are truly bad (precision/recall), and does removing them / cutting their leverage improve return+DD+year-stability OOS per coin — the win condition; (2) leverage-dial effect on return, DD, and **yearly stability** vs matched-fixed-lev baseline; (3) skip/take threshold curve vs base+random+shuffle.

**The real goals (tune toward these):**
- Improve return, risk, and **year-to-year stability for the weak coins too** (BTC/XRP/BNB), not just ETH.
- **Flatten returns across years.** The monster's flaw: returns concentrated in 2020, 2026 already negative. Optimize for yearly consistency, not just cumulative return.
- **Regime-adaptive bot parameters:** learn WHEN to change the bot's own params to fit the market regime (some configs win 2026, some lose) — capture profit across regimes. NOTE: naive regime-switching already failed walk-forward (see [[tradevision-key-findings]]) — do it rigorously, report honestly whether it beats baseline.
- Dual final aim: find the return champions AND tune toward champions that are consistent across all years.

**NN-AS-CONFIG-SELECTOR (Itamar, repeated ask, 2026-06-14):** a primary desired direction — let the NN itself pick the right config in real time, conditioned on coin context + market regime. Concrete evidence motivating it: some configs had 2026 as their WORST year while others had 2026 as their BEST → there's a config↔regime mapping to learn (which config suits which regime/coin), and dynamically selecting it is a path to cross-year consistency. Pursue this, but rigorously: naive regime-switching already FAILED walk-forward (see [[tradevision-key-findings]]) — any config-selector must beat matched baselines out-of-sample and be reported honestly. This is the design objective for the next/corrected training run.

**NETWORK-CHOICE IS A FEATURE + BUILD ON TOP OF THE 3 NETS (Itamar, 2026-06-15, core design):** the new NN must be a regime-adaptive selector of BOTH (a) the config params AND (b) WHICH of the 3 existing networks to apply — GutNet R1 / GutNet Per-Coin / ComboNet — choosing which network+config to use WHEN, WHERE, and on WHICH ASSET. The network choice is itself a FEATURE in the selection. Why: a config can be phenomenal for one week then fail when the regime shifts; the net must learn to match config *style* (fast/slow, risky/safe, short/long-term) AND network to the current market regime (volatility, momentum, distance-from-MA, "market mood"). The 3 nets are a PROVEN achievement (validated DD-reduction + big return boost) — the new net builds ON TOP of them and trains on the DATA THEY PRODUCE (i.e. config × network trade streams, not raw-engine only). This is WHY Itamar insisted on the widest config grid + most features: that breadth IS the correct training data to learn the regime→(config,network) mapping. Practical implication for the next run: training data = the config × {3 networks} cross-product; the selector outputs (config, network) per regime/asset/time. Goal stays: a spike EVERY year and month by always riding the (config,network) that fits the current regime — leveling UP. See [[tradevision-percoin-validation]] (the 3 nets are risk/leverage managers) — combining them per-regime is the new layer.

**CONSISTENCY = LEVEL UP, NOT DOWN (Itamar, 2026-06-15, emphatic correction):** consistency must be achieved by RAISING the weak periods to spike level, NOT by cutting/flattening the big spikes. Spikes are GREAT — he wants a spike EVERY year AND every month. So: (a) DROP the over-extension partial-close take-profit as a "consistency tool" — it levels DOWN (caps spikes, 55.8×→8.9×) = exactly the WRONG direction; keep it shelved/optional only. (b) The right engine is the config-SELECTOR: a spike happens when a config's params fit the current regime (trend/vol); selector keeps you in the config catching the current move → spike every period = leveling up. (c) CHANGE the consistency/Stability leaderboard METRIC from "minimize dispersion / year-gap" (gameable by truncating spikes) to "MAXIMIZE the worst-period return — raise the FLOOR" (reward high returns in EVERY period, not flat-by-truncation). Apply via re-rank from raw sweep results, no VM disruption. (d) Also surface WHAT causes each spike (which market features predict which config spikes) — the selector reveals this. See [[tradevision-overnight-2026-06-15]] over-extension build.
