THE binding design for the TradeVision/Alphic live selector network (Itamar, 2026-06-17, stated explicitly and asked to persist so it survives the chat). Supersedes the static cross-sectional framing. Companion: [[tradevision-nn-iteration-goal]], [[tradevision-overnight-2026-06-16]], [[tradevision-percoin-validation]].

**GOAL:** an asset-agnostic network that connects ALL market-context dots to the win/loss outcome of trades, learns which (config, network, settings) is right for the current market state, and decides LIVE (re-decides every minute/hour/day on prior-candle close). It must "collect the profitable trades and drop the losing ones." Spike every period by riding the (config,network) that fits the regime — level UP, never cut spikes.

**ACTION SPACE = FULL, not a small pool.** All ~235k–236k POSITIVE configs (each = a full param combo: longSMA/reversal-base-candle, tp_difference/TP-spread, tp_count, stop_loss, leverage, stopLooseTP, timeframe) × the 4 networks {none, gutnet_r1, percoin_new, crypto_combo} × the levers already built (leverage dial, etc.). NOT 3-5 configs (a prior wrong suggestion Itamar rejected).

**TWO-PHASE METHOD (Itamar's exact design):**
- **PHASE 1 — trade-outcome predictor / critic (supervised "understanding"):** feed the BILLIONS of trades, each with its full market context + regime + full config + asset + network. The net predicts per trade: will it exit at STOP or in PROFIT, and how profitable (% / r_multiple). Reward correct prediction; iterate over all ~2.573B trades. Learns in which (regime × config × net × asset) context a trade is profitable vs negative.
- **PHASE 2 — invert it → LIVE policy:** give ONLY the minute candles. Minute-by-minute, on the PREVIOUS candle's close, the net decides the full action: enter? / TP count / TP spread / stop / reversal-base-candle (MA) / leverage / network / (i.e. which config from the 235k + net + dial). Reward = realized forward % profit. The Phase-1 critic SCORES candidate actions for the current context → Phase 2 picks the best (no 235k-way softmax). Evaluate STRICTLY walk-forward / OOS (no look-ahead) — it must run live.

**ORDERING (as agreed):** baseline OOS table first (control) → build the rich no-look-ahead feature pipeline (quality-validated) → STREAMING full-data training on ALL 2.573B (shard-by-shard, never all in RAM — the 40M-sample runs were memory-capped stopgaps, NOT the full vision) → Phase-2 live policy + walk-forward → only after signal, generate the per-trade NET dimension (gutnet_r1/percoin_new/crypto_combo via the faithful kernel) and add net conditioning. Gate the heavy net-generation until Phase-2 shows signal.

**RICH PER-TRADE CONTEXT (Itamar's KEY — "the key to everything"; quality + richness is where the value is). Every feature STRICTLY no-look-ahead (only bars before entry).** The net must get the same picture a savvy trader builds top-down:
- **Multi-timeframe stack (monthly → weekly → daily → 4h → 1h → 15m → 5m → 1m):** compute the regime feature set at MULTIPLE timeframes and attach together, so the net sees the high-TF context AND the entry-TF detail (the trader's "open monthly, then weekly, then daily/4h for my trade range, then 1h/15m/5m, then 1m for confirmation").
- **Full config params** (decode config_id).
- **The config's OWN MA:** value, slope, distance in % AND ATR, TIME-SINCE-LAST-CROSS, and CROSS-COUNT in last 24h/7d/30d (← the chop-vs-trend texture: many crossings = chop/whipsaw, few = sustained trend; maps to the W3500 finding).
- **Candle-history texture** preceding entry: range/body/wicks/volume/up-fraction/run-length over recent bars.
- **Multi-horizon regime:** realized vol 1d/3d/7d/30d, momentum/returns multi-horizon, Kaufman efficiency ratio, trend strength, drawdown-from-peak, ATR%, vol-of-vol.
- **Market structure Itamar wants the net to "see":** bull/bear, bullish/bearish flag, rising/falling channel, consolidation-vs-breakout ("waiting for a big move vs already started"), volume + RELATIVE volume ("is the asset in the spotlight today or dormant"), accumulation vs distribution. → To distinguish: calm chop / stormy chop / trend reversal / sustained trend.

**WHAT'S COMPUTABLE FROM OUR OHLCV SUBSTRATE vs NEEDS EXTERNAL DATA (honest):**

Channel/flag/bull-bear from MA-slopes + higher-highs/lows + regression channel; relative-volume (spotlight vs dormant) from volume vs its own average; consolidation/breakout from volatility-compression (squeeze); accumulation/distribution PROXY via OBV / Acc-Dist line.
